# SPEC — tache-api

Source of truth for **what** to build. If something is not here, do not invent it; ask.

## Scope

- V1: tasks CRUD, filtering, pagination, API-key auth, OpenAPI contract, Postgres.
- V2: AI features via a local Ollama instance (optional, behind a port).
- Out of scope: CLI (separate project), web UI, teams/sharing, JWT/OAuth, deployment.

## Domain

### Task

| Field                     | Type                                | Rules                                             |
| ------------------------- | ----------------------------------- | ------------------------------------------------- |
| `id`                      | uuid (`TaskId`)                     | generated by the server                           |
| `title`                   | string                              | required, 1–200 chars, trimmed                    |
| `description`             | string \| null                      | max 5000 chars                                    |
| `status`                  | `todo` \| `doing` \| `done`         | default `todo`                                    |
| `priority`                | `low` \| `medium` \| `high` \| null | default null                                      |
| `tags`                    | string[]                            | max 10, each 1–30 chars, lowercase, unique        |
| `dueDate`                 | ISO date \| null                    | optional                                          |
| `createdAt` / `updatedAt` | ISO datetime                        | server-managed                                    |
| `completedAt`             | ISO datetime \| null                | set when status becomes `done`, cleared otherwise |

Rules:

- Moving to `done` sets `completedAt`; moving away from `done` clears it.
- A task belongs to exactly one user. A user never sees another user's tasks
  (a foreign id returns `404`, not `403`).

### User and API key

- `users`: `id`, `name`, `createdAt`.
- `api_keys`: `id`, `userId`, `keyHash`, `label`, `createdAt`, `revokedAt`.
- Keys look like `tache_<random>`. Only the SHA-256 hash is stored; the plain key
  is shown once at creation (seed script).

## Endpoints (V1)

All under `/v1`, JSON only. Auth: `Authorization: Bearer <api key>` on everything except `/health`.

| Method | Path                 | Purpose                    | Success    |
| ------ | -------------------- | -------------------------- | ---------- |
| GET    | `/health`            | liveness (no auth)         | 200        |
| POST   | `/v1/tasks`          | create task                | 201 + task |
| GET    | `/v1/tasks`          | list with filters          | 200 + page |
| GET    | `/v1/tasks/:id`      | get one                    | 200 + task |
| PATCH  | `/v1/tasks/:id`      | partial update             | 200 + task |
| POST   | `/v1/tasks/:id/done` | shortcut: mark done        | 200 + task |
| DELETE | `/v1/tasks/:id`      | delete                     | 204        |
| GET    | `/v1/openapi.json`   | OpenAPI document (no auth) | 200        |

### List filters (query params)

`status`, `priority`, `tag`, `q` (case-insensitive substring on title/description),
`dueBefore`, `limit` (default 20, max 100), `cursor`.
Order: `createdAt` descending, then `id`.

### Pagination

Cursor-based. Response shape:

```json
{ "items": [/* tasks */], "nextCursor": "opaque-string-or-null" }
```

The cursor is opaque to clients (base64 of `createdAt` + `id`).

## Errors

One shape for every error:

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "…", "details": [] } }
```

| Code               | HTTP | When                                  |
| ------------------ | ---- | ------------------------------------- |
| `VALIDATION_ERROR` | 400  | body/query/params fail Zod validation |
| `UNAUTHENTICATED`  | 401  | missing/invalid/revoked key           |
| `NOT_FOUND`        | 404  | task missing or owned by someone else |
| `INTERNAL_ERROR`   | 500  | unexpected; never leak stack traces   |

## Config (env vars, validated at startup)

`PORT`, `DATABASE_URL`, `NODE_ENV`; V2 only: `OLLAMA_URL`, `OLLAMA_MODEL`,
`OLLAMA_EMBED_MODEL`. The app must fail fast with a clear message if a required
variable is missing or malformed.

## V2 — AI features (Ollama)

Port: `AiAssistant` in `domain/`, adapter in `adapters/ai/`. Use cases depend on the
port only. If Ollama is unreachable, AI endpoints return `503` with code
`AI_UNAVAILABLE`; the rest of the API is unaffected.

1. **Suggest priority** — `POST /v1/tasks/:id/suggest-priority` returns
   `{ "priority": "low|medium|high", "reason": "…" }`. Does **not** modify the task.
   The model output is validated with Zod; invalid output → `502`.
2. **Find duplicates** — `GET /v1/tasks/:id/duplicates` returns similar tasks of the
   same user, using embeddings (Ollama embed endpoint) and cosine similarity
   computed in TypeScript. Store embeddings in a `task_embeddings` table
   (`taskId`, `model`, `vector` as `real[]`). Recompute when title/description change.

AI features must be useful without being required: every task works without them.

## Non-functional

- Every endpoint documented in the OpenAPI document, generated from Zod schemas.
- Integration tests run against a separate database (`tache_test`).
- Logs: one structured JSON line per request (method, path, status, duration). Never log keys.
